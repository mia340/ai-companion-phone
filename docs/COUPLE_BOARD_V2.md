# 心跳飞行棋 V2.2 · 固定分屏、面对面互动与长期记忆说明

版本：`0.5.0-alpha.5.8.2`
状态：V2.2 Alpha


## 0. V2.2 交互约束

- 游戏固定为现实面对面：双方在同一现实空间一起玩，可能在房间、酒店或其他实际空间；系统不擅自猜具体地点。
- 棋盘上的花店、公园、电影院、床边等全部只是虚构棋盘格和视觉舞台，不代表现实位置，也不会被写成真实共同经历。
- 每道题只属于本回合掷骰的人。另一方必须可以自然回应、追问、接话或一起延长互动，但不会被强制承担同一道题。
- 游戏页固定为上半地图、下半互动的连续分屏；题目出现后不再弹出可拉伸的大面板，也不会为了看地图反复展开/收起页面。地图与对话始终同时可见。
- 对话气泡不再重复标角色名字，人物身份主要通过左右位置与头像区分。
- 当前题目不能更换。用户自己的题若想跳过，需要向角色请求并由角色明确同意；角色自己的题如果角色主动提出跳过，则由用户决定是否同意。
- “跳过题目继续游戏”需要对方同意，但任何人都可以随时拒绝现实身体动作、停止当前现实互动或结束整局，这些不需要对方批准。

## 1. 这一版改变了什么

V2 不再把心跳飞行棋当作“掷骰子 → 抽题 → 点完成”的小游戏。棋盘只负责创造相遇节点，真正的核心是角色和用户在每个节点上发生的连续互动。

本版的四条原则：

1. **角色不重置。** 游戏中的角色继续使用原角色卡、语言习惯、边界、关系设定和长期 Memory，不因为“情侣游戏”而被换成统一恋爱模板。
2. **题目只是开场。** 单人题也必须形成双方互动；一方先回答，另一方按自己的人设与记忆回应，双方可以继续聊，也可以自然收住。
3. **棋局不催进度。** 一道题可以聊很多轮。角色可以表达“这段差不多了”，用户仍然可以选择继续；只有双方都真正参与过，才允许把这一段作为“完成互动”推进棋局。
4. **棋局结束，关系不重置。** 已完成互动会经过 Memory Bridge 写入长期记忆。下一次普通聊天、下一局游戏和 Shared Timeline 都可以再次使用这些真实经历。

## 2. Character Context：角色为什么不应该 OOC

每次角色需要回应游戏内容时，运行时会重新建立角色上下文：

- `persona`
- `cardDescription`
- `cardPersonality`
- `speakingStyle`
- `background`
- `values`
- `habits`
- `likes / dislikes`
- `boundaries`
- `relationship`
- `scenario`
- `systemPrompt`
- `postHistoryInstructions`
- 当前会话状态
- 与本题相关的长期 Memory
- 与角色相关、可验证的 Shared Timeline 事件
- 当前棋盘格（仅视觉舞台）、题目、最近互动文本

Prompt 明确规定：**角色一致性和记忆连续性优先于游戏气氛。** 不再规定“害羞 / 吃醋 / 反撩”等固定反应类型，角色应当按自己原本的人设做反应。

如果角色明确引用过去共同经历，模型需要同时返回支撑该说法的 Memory / Timeline evidence id。不存在的 evidence id 会被拒绝，避免为了“沉浸感”临时编造过去。

V2 还增加了 **Role Continuity Audit**：候选回复生成后，会用同一个角色卡、边界、Memory/Timeline 再做一次低温审校。审校器不要求角色“更甜”或套固定恋爱表现，只判断是否明显违背该角色已经存在的人设、边界、关系与证据；第一次不通过时会带着具体冲突理由自动重生成一次。

## 3. Memory Retrieval：不是把全部记忆塞给模型

V2 会使用当前题目和最近几句互动作为检索 query，从该角色的：

- 当前聊天记忆
- 角色级共享记忆
- Shared Timeline

中选择真正相关的内容。高重要度、锁定、关系层、共享层以及与本题关键词命中的记忆优先。

这样做的目标不是“模型看见越多越好”，而是让角色在正确的时候想起正确的事。

## 4. Memory Bridge：游戏怎么进入总记忆

完成一次双方互动后，V2 做两层写入。

### 第一层：真实互动事件

这一层不依赖 AI 提炼，直接把这次真正发生过的对话保存成共享事件。例如：

> 心跳飞行棋（棋盘格：沙发边，仅游戏舞台）：用户：「我喜欢你从后面抱我。」；阿澈：「好，我会记住。」

它记录的是“双方确实这样说过”，不会把问题里的假设改成事实。

该记忆使用：

- `category: event`
- `layer: shared`
- `scope: character`
- `sourceType: automatic`
- `note: couple-board:<gameId>:<interactionId>`

因此它进入长期 Memory，也能被 Shared Timeline 识别为 `shared-event`。

### 第二层：稳定语义记忆

如果 AI 配置可用，再尝试从互动里提炼最多 4 条真正稳定的信息，例如：

- 用户明确的长期偏好
- 角色自己明确表达的偏好
- 边界
- 关系中以后值得记住的稳定事实

提炼器必须把内容分类成：

- `stable`
- `hypothetical`
- `transient`

只有 `stable` 会写入 Memory。假设题、幻想、条件句、临时害羞、游戏题目本身都不能被写成现实事实。

如果 AI 暂时不可用，第一层“真实互动事件”仍然会保存，不会因为模型调用失败导致这局完全失忆。

## 5. 单人题为什么也是双人互动

V2 的单人题只表示“谁先开始”，不表示“只有谁参与”。

用户先回答时：

`题目 → 用户回答 → 角色基于人设/记忆回应 → 用户可继续 → 角色继续回应 → 双方决定何时结束 → Memory Bridge → 下一回合`

角色先回答时：

`题目 → 角色自己回答 → 用户回应 → 角色继续 → 双方决定何时结束 → Memory Bridge → 下一回合`

只有双方都至少真实回应过一次，才可以使用“这段聊够了 · 继续走”。

## 6. 角色自己掷骰子

V2 中用户仍负责自己的回合；轮到角色时，不再需要用户替角色机械点一次骰子。

当：

- 当前玩家是角色
- 没有未完成题目
- 没有未处理事件卡
- 不在动画/保存中

角色会自动进入掷骰流程。骰子动画结束后，小人沿地图节点逐格移动，再触发对应地点的内容。

## 7. 新地图

原来的规则索引仍然保持 `0..29`，因此旧对局结构不需要升级数据库；表现层改成 30 个“约会地点”：

家门口 → 街角 → 便利店 → 甜品店 → 公园 → 夜市 → 电影院 → 河边 → 月光桥 → 天台 → 回家 → 客厅 → 沙发边 → 阳台 → 床边 → 心跳终点。

地点现在只作为**棋盘表现层上下文**：角色可以知道棋子停在“河边”“沙发边”或“床边”这一格，但不得推断双方现实中就在这些地方。现实地点只有用户或既有可信记忆明确说明时才可使用。

## 8. 两种视觉模式

### 像素约会

- 两个完整的小人站在地图上
- 角色有头、身体、手脚和脚下阴影，不再只是头像圆点
- 小人随真实棋盘位置逐格移动
- 角色回合自动掷骰
- 像素路线、地点、建筑、夜景共同构成小型约会地图

### 浪漫地图

使用相同的游戏状态和地图索引，但表现为更柔和的约会路线和圆形棋子。

视觉模式只影响 Presentation，不改变题库、记忆、棋盘位置或胜负。

## 9. 数据层

本版没有新增 IndexedDB store，也没有升级数据库版本。新增的游戏互动 ledger 继续复用 `appCustomizations` 的非索引字段保存，因此：

- IndexedDB：V18 不变
- Backup：V12 不变
- Launcher Grid：V13 不变
- HomeLayout revision：13 不变
- CoupleBoardPreferences：V2 不变
- CoupleBoardArchive：V1 不变
- CoupleBoard Interaction Ledger：V1（复用 appCustomizations）

旧的 V1/V1.4 对局没有 `visualMode` 时默认按浪漫地图恢复。

## 10. 安全与真实性

V2 继续保留：

- L4/L5 18+ 门禁
- 明确未成年角色硬阻断
- 不允许换题；跳过题目继续游戏需要对方同意，同时保留随时停止现实身体动作或结束整局的权利
- 现实身体动作不替用户默认同意
- Memory evidence id 校验
- Timeline `promise / goal / story` 排除
- reduced-motion

“沉浸”不意味着可以编造共同经历。游戏里的真实新互动可以成为新记忆；过去不存在的事仍然不能为了戏剧效果被说成发生过。

## 10.1 V2.2 固定分屏与跳过同意

V2.2 把游戏中的“地图”和“互动”固定为同一屏幕的上下两半：上半地图持续显示双方小人、当前位置和路线；下半互动持续显示题目、双方对话与输入区。互动区域内部可以滚动，但不会再通过拖拽改变整个页面结构。这样一题聊十几轮时，地图仍然一直在场，页面不会反复跳来跳去。

题目规则也改成“一掷一题”：当前骰子落到哪一道题，就必须围绕这一题继续，不提供“换一题”入口，也不再用 Memory 题去覆盖当前题。

跳过使用双方同意协议：

- 用户是本轮答题人时，可点击“请求跳过”；角色会按自己的人设、长期 Memory、边界和当前上下文决定同意或不同意，而不是系统自动批准。
- 角色是本轮答题人时，角色如果确实不愿继续，可以在自然回应中主动提出跳过；界面会把决定权交给用户，用户可以“同意跳过”或“继续这题”。
- 跳过请求与结果会保存在 Interaction Ledger 中，刷新后不会丢失当前同意状态。
- 这套规则只控制“是否跳过题目并继续棋局”。现实中的接触、亲吻、成人动作等仍然可以被任意一方直接拒绝或停止，绝不因为棋局规则而变成强制。

## 11. 当前 V2 Alpha 的边界

这一版已经把长期 Memory、自由互动、角色自动掷骰、双视觉地图和像素小人主链打通，但仍是 V2 Alpha：

- 像素角色目前是通用 CSS sprite，还没有为每个角色自动生成独立服装/发型 spritesheet。
- 事件卡仍以事件演出为主，没有像问题卡一样进入完整自由对话 ledger。
- 地点目前进入角色上下文，但“不同地点动态改变抽题权重”留给下一阶段。
- Memory Bridge 目前优先保留真实事件，再由模型提炼稳定偏好；后续可继续做更细的冲突/时间版本管理。

这些边界不会影响旧数据兼容，也不会阻塞当前 V2 的主互动链。

## 12. 代码落点

V2 不是把更多逻辑继续堆进 View，而是拆出三条新的服务边界：

```text
src/services/coupleBoardInteractionService.ts
  角色上下文 / Memory 检索 / Shared Timeline / 角色回应 / evidence 校验 / Interaction Ledger

src/services/coupleBoardMemoryBridge.ts
  已完成互动 → 真实共享事件 → 稳定语义记忆

src/services/coupleBoardMapService.ts
  30 地点路线 / 地点语义 / 视觉坐标

src/components/couple-board/CoupleBoardPixelSprite.vue
  像素小人表现层

src/views/CoupleBoardView.vue
  只负责把棋盘、互动、Memory Bridge 与表现层编排起来
```

这使后续继续增加 spritesheet、地图主题、地点题库偏置或事件卡自由对话时，不需要重新把所有逻辑绑回一个组件。

## 13. 一次题目互动的完整生命周期

```text
落到题目格
  ↓
建立 / 恢复 Interaction Ledger
  ↓
读取角色卡 + Conversation State + 相关 Memory + Shared Timeline
  ↓
先手回答（用户或角色）
  ↓
另一方回应
  ↓
自由继续多轮
  ↓
角色可提出自然收尾；玩家仍可继续
  ↓
双方至少各有一次真实回应
  ↓
用户确认结束这一段
  ↓
Memory Bridge 保存真实 shared-event
  ↓
可用 AI 时再提炼 stable memory
  ↓
关闭 Interaction
  ↓
棋盘继续
```

如果页面刷新，尚未关闭的 Interaction 会按 `gameId + promptId` 找回，而不是只恢复棋子后把正在聊的话题丢掉。

## 14. 发布后的人工验收重点

1. 选任意角色进入像素模式，确认两个完整小人都在地图上且位置对应双方真实 position。
2. 用户掷骰后，小人按每一步移动到目标地点；骰子动画必须停止。
3. 轮到角色后，不点击骰子，确认角色会自行掷骰并移动。
4. 抽到“用户先答”的单人题：用户发送回答后，角色必须回应；未形成双方回应前“继续走”不可用。
5. 抽到“角色先答”的题：角色应先按自己人设回答，用户回应后角色可以继续接话。
6. 连续多聊几轮，确认系统不强制推进棋盘；角色返回自然收尾时，仍可以点“我还想继续”。
7. 结束一段互动后，到 Memory Center 检查出现 `couple-board:<gameId>:<interactionId>` 来源的记忆；Shared Timeline 可看到 shared event 投影。
8. 对假设题说“如果以后……”，确认不会被提炼成“已经发生”的现实事实。
9. 刷新正在进行的一局，再点“继续”，确认当前未结束 Interaction 可以恢复。
10. 新开一局切换浪漫地图，确认视觉变化不会改变题库、Memory 或棋局规则。
11. L4/L5 继续要求成年人确认；明确未成年角色仍不能进入成人/私房档。
12. 开启系统 reduced-motion 后，走路/骰子/浮动动画应降级而不影响可玩性。
