# 心跳飞行棋 V1.1 · 同类项目学习记录 · 2026-09-22

> 目标：学习公开“小手机”项目如何把情侣空间、互动玩法、长期记忆和 local-first 数据做成持续体验。只吸收产品/架构方法，不复制第三方代码、素材或 Prompt。完整样本 URL 继续以 `REFERENCE_PROJECTS.md` 为索引。

## 本轮重点观察

- **Love Boat / 小船机**：网页端把聊天之外的共同空间、纪念日、日常模块组织成“关系体验”，说明情侣玩法不应只是一次性弹窗。
- **Miya**：把情侣空间做成独立模块并与时间线/照片/秘密等生活化内容并列，强调“共同经历”比单纯堆题量更有黏性。
- **StoryPhone / 叙事诗小手机**：长期记忆、RAG 与互动卡片并存，说明互动游戏可以引用长期上下文，但必须经过明确 Runtime 边界。
- **InternalBeyond Mobile**：local-first、多模块与记忆连续性并行，适合本项目继续坚持“App Surface 不拥有事实、Runtime 控制权限”。
- **Melt**：本地优先、记忆/日记/关系类数据放在同一长期体验里，提醒我们不要为了小游戏复制新的事实数据库。

## V1.1 真正吸收的机制

### 1. 专属题库，而不是无限内置题

用户自己写的一两道“只有我们懂”的题，比再增加几十道通用题更能形成专属感。实现上让题库成为偏好数据，并在开局冻结进 session，避免跨版本/跨编辑漂移。

### 2. 记忆连续性，但 evidence-first

不让模型自由回忆“你们以前怎样”，而是：

```text
Memory evidence → 受限 Provider 输入 → evidence id 校验 → 当前局题目
```

没有 evidence 就不生成；Promise 也不当作已经发生的回忆。

### 3. 事件卡承担“共同空间的呼吸感”

不是每一格都要求回答问题。独立事件卡用轻量确定性效果制造节奏变化，同时不会污染 Relationship/Memory。

### 4. 结算展示共同经历，不评价关系

Heartbeat Highlights 只总结本局真实日志：完成、跳过、事件、回忆题。它不计算“亲密度等级”、不判断谁更爱谁，也不把游戏分数反写关系状态。

### 5. Local-first 继续是默认

自定义题库和局内 AI 题都复用已有本地持久化；API Key / Provider 沿用全局模型设置。没有为了 V1.1 引入新的云账户、远端事实源或数据库迁移。

## 没有照搬的内容

- 不复制任何第三方仓库代码或视觉素材。
- 不执行参考项目中的未知 HTML/JS。
- 不因为别的项目有更多 App 就继续扩 Launcher。
- 不把模型生成的“回忆”直接写进 Memory。
- 不做关系评分、匹配度或胜负型亲密度结论。

本轮结论：V1.1 应该让游戏更像“你们自己的共同空间入口”，但事实权仍属于现有 Memory / Conversation / Shared Event Runtime；游戏只是受控的互动投影。
