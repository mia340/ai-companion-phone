# 知间 · 产品原则（2026-09-16）

- 对标微信的信息架构、页面层级和手机聊天操作体验；不要把聊天、通讯录、朋友圈、钱包拆成四个桌面 App，也不要四个页面全部堆到底部弹窗。
- 桌面只留一个「知间」入口。内部四个底部标签为「知间」「通讯录」「发现」「我」：发现 → 朋友圈；我 → 个人资料、空间设置、钱包、设置。四个主标签页本身也提供返回空间桌面的入口；聊天房间、朋友圈动态详情、空间设置和资料编辑属于二级页面，保留明确返回路径。
- 视觉取向：清爽、克制、易扫读，底部导航固定，聊天与朋友圈通知保留未读提示，避免复杂大面积玻璃拟态和多余浮层。
- 个性签名是 UserProfile.signature 的公开展示字段，可为空、最多 80 字；它不是人物身份、世界事实或 Persona Prompt。角色专属 Persona 仍按原规则绑定，不能凭 {{user}} 推断个人资料。
- 钱包当前没有真实账户、支付或转账业务；集成入口不代表已实现金融功能，页面必须明确状态，禁止显示假余额或伪造付款成功。
- 保留原 IndexedDB 用户数据与历史路由，升级不得清空聊天或覆盖角色卡。参考微信交互，不复用微信名称、商标和专有视觉资产。

- 空间桌面当前只保留「知间 / 我的资料 / 记忆 / 世界 / 数据备份 / 设置」六个核心入口，不用 Dock 重复展示同一批 App；音乐、日记、海龟汤等已有模块可保留代码与历史路由，但不占当前核心桌面。
- 朋友圈可见性和黑名单必须由本地 Runtime 校验，不能只靠 UI 隐藏；模型不能自行决定谁有权限看到动态。
- 「时光 / 关系脉络」只负责把真实 evidence 做可追溯投影，不做关系评分、好感度排名或“谁对谁错”判断。明确关系阶段只能来自已有结构化 relationship state；AI 只能解释 Runtime 提供的节点，必须带完整 provenance，且未经用户确认不得持久化或进入角色 Prompt。
