# 社区角色卡 Persona 兼容审计（2026-09-13）

本审计基于用户提供的社区资源包，用于验证“不能针对某一张卡写特判”的工程要求。

## 样本概况

- ZIP 内条目：58
- 成功读取 JSON：49
- 发现明确用户 Persona / 用户背景语义标签的文件：13
- 其它文件包含世界书、预设、正则、工具资源或只有普通 `{{user}}` 剧情引用，不应强制创建 Persona。

## 观察到的 Persona 表达形式

1. 世界书条目标签：`User设定`、`user人设`、`user基本情况`、`{{user}}人设辅助`、`user人设（自行粘贴）`。
2. 作者备注标签：`[用户设定(...)]`、`[我的设定]`，并且标签可能和作者说明写在同一行。
3. 正文模板：`{{user}}我是...`、`{{user}}[用户]是{...}`、`姓名: ... / 年龄: ...`、HTML 人物档案。
4. 社区扩展对象：`user_persona`、`user_profile`、`player_profile` 等对象/字符串形式。

## 明确需要排除的误判来源

- `user_personal_room` / 用户住所 / 房间
- 座驾、衣橱、头像、手机、相册、日记、联系人、NPC
- “user 人设自拟”“请填写用户设定”一类只有建议、没有具体身份事实的作者说明
- 普通剧情句：`{{user}}希望...`、`{{char}}照顾{{user}}...`

## 兼容策略

识别采用三层门槛：

1. **来源语义**：字段名或区块标签明确表示用户 Persona；
2. **内容信号**：姓名、年龄、性别、身高、职业/身份等结构化或自然语言身份信号；
3. **误判排除**：环境资源、设备资源、NPC 资源和“自拟提示”不得转 Persona。

不使用任何特定角色姓名或特定用户姓名硬编码。

## 安全原则

如果角色卡本身没有独立用户 Persona，只包含普通 `{{user}}` 占位或剧情关系，导入器必须保持“不猜姓名、不伪造 Persona”，运行时改用当前聊天已绑定 Persona。

- 17 份被识别为世界书或 Prompt 预设并主动拒绝，这属于正确的资源路由行为；
- 32 份角色卡中 17 份检测到独立用户 Persona；
- 验证了 `player_profile: { 年龄: "29岁" }`、英文 `user_profile: { age: "31 years old", height: "172 cm" }`、同行 `[我的设定]...` 和 `user_personal_room` 误判保护。

该语料扫描只用于发布前审计，不再作为正式 Vitest 依赖外部文件路径。
