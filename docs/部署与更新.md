# 部署与更新 · 长期通用流程

## 当前发布：V0.5.0-alpha.5.6.0

本版本是心跳飞行棋 V1.1：新增自定义题库、基于真实共同回忆 evidence 的 AI 出题、情侣事件卡、Heartbeat Highlights 与交互动效。IndexedDB 仍为 V18、Backup 仍为 V12、HomeLayout revision 仍为 13，无数据迁移。


当前版本号、IndexedDB / Backup 版本和本轮专项验收，以 `PROJECT_STATUS.md` 与 `releases/<当前版本>_部署与更新.md` 为准。本文件只保留长期固定门禁。

默认 Windows 工作目录：

```text
D:\ai
D:\ai\ai-companion-phone-git-clean
```

固定顺序：**解压新版本 → 第一次验证 → 复制到 Git 仓库 → 第二次验证 → 提交推送 → GitHub Actions / Pages 确认**。

## 1. 解压新版本

把当次 `*-windows-safe.zip` 放到 `D:\ai`。不要把旧目录里的 `node_modules`、`dist` 复制进新源码。

每次先检查：

```powershell
Test-Path $zip
Test-Path "$new\package.json"
Test-Path "$new\package-lock.json"
```

## 2. 第一次验证

进入新源码目录：

```powershell
npm ci
npm run verify
```

`npm run verify` 等价于：

```powershell
npm test
npm run build
```

**只有测试、vue-tsc 和 Vite Build 都成功，才允许继续。**

如果出现红色错误，停止部署，把 `npm run verify` 最后一段输出用于定位；不要强行 push。

## 3. 检查 Git 仓库

```powershell
cd D:\ai\ai-companion-phone-git-clean
git status
```

先确认没有未提交的个人修改，避免 `/MIR` 覆盖工作区。

## 4. 复制源码

使用：

```powershell
robocopy $new $repo /MIR /XD ".git" "node_modules" "dist"
```

`robocopy` 的 1、2、3 等返回码不一定代表失败；以最终 `FAILED` 统计和 `git status` 为准。

## 5. 第二次验证

复制进 Git 仓库后再次：

```powershell
cd D:\ai\ai-companion-phone-git-clean
npm ci
npm run verify
```

这一步也必须全绿。

## 6. 提交与推送

```powershell
git add -A
git status
git commit -m "release: <version>"
git push origin main
```

如果 commit 已成功，而 `git push` 只因为 `github.com:443` 网络失败，**不要重新复制、不要重新 `git add`、不要重新 commit**。网络恢复后只执行：

```powershell
git push origin main
```

## 7. GitHub Pages 确认

1. 打开 GitHub Actions，等待最新 workflow 绿色成功；
2. 再打开 GitHub Pages；
3. 若 PWA 仍显示旧版，关闭旧页面后重新打开，或普通刷新一次；
4. **不要通过“清除站点数据”强制更新。**

## 8. 数据保护原则

- 不删除旧 GitHub Pages 站点；
- 不清除浏览器站点数据、IndexedDB、LocalStorage；
- 不手工改 Dexie 数据库版本绕过迁移；
- 大版本升级前优先导出项目内置备份；
- 新版本无数据库迁移时，应保留旧角色、聊天、记忆、朋友圈、世界书、Persona、资源绑定和桌面外观。

## 9. 发布前人工验收

每次至少检查：

1. 主屏 / Dock / 本轮新增入口能打开；
2. 聊天可加载已有会话；
3. 新旧角色卡、WorldBook、Preset、Regex 不被升级破坏；
4. 数据备份能导出并读取摘要；
5. 本轮新增功能按 `docs/releases/<版本>_部署与更新.md` 验收；
6. 浏览器刷新 / PWA 重开后关键状态仍存在。

## 10. 文档位置

所有 Markdown 文档统一保存在 `docs/`：

- 当前状态：`docs/PROJECT_STATUS.md`
- 当前架构：`docs/ARCHITECTURE.md`
- 版本记录：`docs/CHANGELOG.md`
- 逐版本交付：`docs/releases/`
- 参考研究：`docs/research/`

## 11. V0.5 发布安全门禁

从 V0.5.0-alpha.5.1.26 起，发布链新增仓库级安全检查：

```powershell
npm run release:git-preflight
npm run release:git-working
npm run release:staged-check
```

- `release:git-preflight`：同步前要求 `main`、存在 `origin`、工作区 clean，且不存在 ignored-but-tracked / `node_modules` / `dist` / `*.tsbuildinfo` / `.env*` Git 污染。
- `release:git-working`：同步后允许源码变更，但继续检查分支、remote 和 Git 跟踪边界。
- `release:staged-check`：`git add -A` 后只允许项目源码/文档进入暂存区；依赖、构建产物、tsbuildinfo、真实 `.env*` 一律阻止 commit。
- `npm run verify` 已统一包含 `release:source-check`，GitHub Actions 与本地使用同一个质量门禁。

发布脚本不得用关闭 `.gitignore`、跳过测试或强制提交的方式绕过这些检查。
