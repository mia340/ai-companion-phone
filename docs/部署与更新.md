# 部署与更新 · 长期通用流程

当前版本号、IndexedDB / Backup 版本和本轮专项验收，以 `PROJECT_STATUS.md` 与 `releases/<当前版本>_部署与更新.md` 为准。本文件只保留不随版本频繁变化的流程。

## 1. 推荐：全新目录安装

不要把旧目录里的 `node_modules` 复制到新源码中。

```powershell
npm ci
npm run verify
```

`npm run verify` 等价于：

```powershell
npm test
npm run build
```

只有测试与 Build 都通过后才部署。

## 2. 更新原则

- **不要清空浏览器站点数据**，除非明确是在做破坏性测试；
- 不要手工改 IndexedDB 版本来“绕过”迁移；
- 新版本若没有数据库迁移，应保留旧角色、聊天、记忆、朋友圈、世界书、Persona、资源绑定和外观设置；
- 先用项目的数据备份功能导出一份备份，再进行大版本升级。

## 3. Git 常用命令

```powershell
git status
git add .
git commit -m "release: <version>"
git push
```

GitHub Pages / CI 若以 `npm run verify` 为发布门禁，任何测试或 Build 失败都应阻止部署，不要跳过。

## 4. 发布前人工验收

每次至少检查：

1. 主屏与主要导航能打开；
2. 聊天可加载已有会话；
3. 新旧角色卡、WorldBook、Preset、Regex 不被升级破坏；
4. 数据备份能导出并能读取摘要；
5. 本轮新增功能按对应 `docs/releases/<版本>_部署与更新.md` 验收；
6. 浏览器刷新 / PWA 重开后关键状态仍存在。
