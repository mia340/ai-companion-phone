# 部署与更新

> 当前示例版本：**V0.4.6.0**。

## 1. 解压

```text
D:\ai\ai-companion-phone-v0.4.6.0
```

确认直接包含 `package.json / src / docs / scripts / public`，不要套娃目录。

## 2. 覆盖 Git 工作目录

```powershell
cd "D:\ai"

robocopy `
  ".\ai-companion-phone-v0.4.6.0" `
  ".\ai-companion-phone-git-clean" `
  /E `
  /XD .git node_modules dist `
  /XF "*.tsbuildinfo" `
  /R:2 `
  /W:1
```

必须确认：

```text
失败        0
```

## 3. 检查版本

```powershell
cd "D:\ai\ai-companion-phone-git-clean"
Select-String '"version"' package.json
```

应看到：

```text
"version": "0.4.6.0"
```

## 4. Build

首次没有依赖时先：

```powershell
npm install
```

然后：

```powershell
npm run build
```

成功应经过 `vue-tsc -b`、`vite build`、PWA generateSW，并生成 `dist/sw.js`。

出现 `error TSxxxx` 时不要 commit / push。

## 5. 开发运行

```powershell
npm run dev
```

手机局域网：

```powershell
npm run dev -- --host 0.0.0.0
```

## 6. Git

Build 与测试通过后：

```powershell
git status
git add .
git status
git commit -m "refactor: Character Card compatibility alignment v0.4.6.0"
git push origin main
```

若 `git push` 因 `github.com:443` 失败但 commit 已成功，不要重复 commit；网络恢复后只重试 `git push origin main`。

## 7. V0.4.6.0 用户验收测试

协议级测试由开发回归负责。更新后建议只做 6 项真实验收：

1. **V2/V3 原卡阅读器**：确认 creator notes 可见，但 Prompt Debug 的 `creator_notes 进入 Prompt` 为“否/0 Token”。
2. **带 system_prompt / post_history 的卡**：Prompt Debug 查看 override 模式；含 `{{original}}` 的卡应显示 replace-with-original。
3. **多开场**：新聊天可选默认、备用、随机、自由开局；自由开局不能偷偷沿用 first_mes 当前场景。
4. **复杂世界书 / Regex UI**：场景合并继续按作者状态 UI；漏字段时优先看到 Community UI 状态继承；历史也不足时可出现“紧凑状态补全”，但第一版正文不能被第二次调用重写。Token usage 若为 2 次调用，第二次应明显小于第一轮完整 Prompt。
5. **V3 nickname / 资源**：带 nickname 的 V3 卡，Prompt Debug 的 `{{char}}` 宏应显示 nickname；V3 导出后仍是 `chara_card_v3`。
6. **旧功能回归**：论坛/微信 Focus、三种呈现、资源库移动端宽度、多会话都应保持。

如果这些通过，就可以提交 Git。
