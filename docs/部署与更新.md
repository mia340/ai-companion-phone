# 部署与更新

> 当前示例版本：**V0.4.7.0**。

## 1. 解压

```text
D:\ai\ai-companion-phone-v0.4.7.0
```

确认直接包含 `package.json / src / docs / scripts / public`，不要套娃目录。

## 2. 覆盖 Git 工作目录

```powershell
cd "D:\ai"

robocopy `
  ".\ai-companion-phone-v0.4.7.0" `
  ".\ai-companion-phone-git-clean" `
  /E `
  /XD .git node_modules dist `
  /XF "*.tsbuildinfo" `
  /R:2 `
  /W:1
```

必须确认：

```text
失败        0
```

## 3. 检查版本

```powershell
cd "D:\ai\ai-companion-phone-git-clean"
Select-String '"version"' package.json
```

应看到：

```text
"version": "0.4.7.0"
```

## 4. Build

首次没有依赖时先：

```powershell
npm install
```

然后：

```powershell
npm run build
```

成功应经过 `vue-tsc -b`、`vite build`、PWA generateSW，并生成 `dist/sw.js`。

出现 `error TSxxxx` 时不要 commit / push。

## 5. 开发运行

```powershell
npm run dev
```

手机局域网：

```powershell
npm run dev -- --host 0.0.0.0
```

## 6. Git

Build 与测试通过后：

```powershell
git status
git add .
git status
git commit -m "refactor: Regex Pipeline V2 and renderer separation v0.4.7.0"
git push origin main
```

若 `git push` 因 `github.com:443` 失败但 commit 已成功，不要重复 commit；网络恢复后只重试 `git push origin main`。

## 7. V0.4.7.0 用户验收测试

协议级 Regex / Depth / placement 组合由开发回归负责。更新后普通使用只建议做 6 项真实验收：

1. **复杂状态 UI**：找一张开场和后续都带作者状态栏的卡。开场 UI 应正常；继续聊天后，显示层可以变成作者 HTML/UI，但 Prompt Debug 的历史不应被整段 HTML 污染。
2. **显示专用 Regex**：找 `markdownOnly=true` 的社区 Regex。用户看到转换后的内容；下一轮 Prompt Debug 的“发给 AI 的临时改写”不应因为它而出现同名脚本。
3. **AI 隐藏 Regex**：找 `promptOnly=true` 或 `markdownOnly+promptOnly` 的脚本。屏幕按作者设置显示，而下一轮 Prompt Debug 应在“发给 AI 的临时改写”看到对应脚本。
4. **历史 Depth**：无需手造测试卡；正常使用带 `minDepth/maxDepth` 的真实资源时，只观察 Prompt Debug 是否出现“因历史深度跳过”。协议准确性由自动回归负责。
5. **编辑消息**：编辑一条带 Regex 的消息。只有作者设置 `runOnEdit=true` 的脚本允许重跑；编辑后不能把显示 HTML 写进 canonical 历史。
6. **旧功能回归**：快速检查默认/备用/自由开场、论坛或微信 Resource Session、纯手机/场景合并/动作台词分离、资源库移动端宽度和多会话。

如果这些通过，就可以提交 Git。
