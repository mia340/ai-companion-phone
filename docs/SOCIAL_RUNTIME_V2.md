# Social Runtime V2 · V0.5.0-alpha.5.1

## 目标

V1 解决了“朋友圈评论任务离开页面后仍能继续”和“用户回复角色后角色继续接话”。V2 进一步解决“谁应该出现、多久出现一次、谁有权限参与”的问题，并把未读互动变成用户可见的通知。

## 决策信号

Social Runtime 不维护隐藏的恋爱/亲密度积分，也不凭空推断角色关系。候选角色权重只使用当前项目已有、可解释的数据：

- 最近包含该角色的会话更新时间；
- 该角色已有的共享记忆数量；
- 当前朋友圈正文与角色姓名、身份、标签、喜好、共享记忆的文本相关性；
- 该角色最近一次 Social Runtime 自动行动距今多久；
- 用户为该角色选择的互动频率：安静 / 自然 / 活跃。

这些信号只决定“更可能由谁参与”，不会改变角色卡事实，也不会写入隐藏关系值。

## 每角色朋友圈权限

每个角色都有独立 Social Profile：

- 可以看朋友圈；
- 可以点赞；
- 可以评论；
- 可以接话；
- 可以主动发动态；
- 互动频率：安静 / 自然 / 活跃。

“主动发动态”只限制后台自主行为。用户在朋友圈里手动选择“让好友发一条”仍然可以执行，避免设置把手动创作入口锁死。

## 冷却

Social Runtime 会降低刚刚自动互动过的角色的候选权重，避免同一角色连续刷屏。不同互动频率使用不同冷却窗口：安静最长，活跃最短。冷却只降低权重，不永久禁止角色出现。

## 新互动通知

角色评论用户的动态，或回复用户的评论时，会写入 `socialNotifications`：

- 朋友圈页顶部显示未读数量；
- 空间桌面“知间”图标聚合显示未读角标；
- 打开“新互动”面板可查看最近评论与回复；
- 点击通知会回到对应动态。

点赞目前只增加动态点赞数，不单独制造通知，避免通知噪声。

## 数据

- IndexedDB：V18
- 新表：`socialProfiles`、`socialNotifications`
- Social Runtime 队列仍为 `socialActivities`
- Backup：V12
  - 备份 `socialProfiles`，因为它是用户配置；
  - 不备份 `socialActivities`，因为队列是可重建运行时元数据；
  - 不备份 `socialNotifications`，因为通知只保存本地未读状态，正文仍由朋友圈动态/评论恢复。

## 群聊后续

V2 的角色权限、活跃度、冷却与加权候选选择可直接复用于后续 Group Chat Speaker Scheduler。群聊会新增自己的 channel/context，而不会复制一套“随机挑角色”的逻辑。

## V0.5.0-alpha.5.1.6：空间可见性与黑名单

「我 → 空间设置」增加整体可见范围与黑名单，并把权限校验接入 Runtime，而不是只做页面开关：

- `private / 仅自己`：用户新动态不创建角色自动评论/点赞任务；
- 黑名单角色：不进入 Social Candidate、不参与自主发动态；
- 已排队任务执行前再次读取空间设置，权限失效则标记 `cancelled`；
- 用户直接回复角色评论时同样检查整体可见性与黑名单；
- 单角色“谁可以看 / 不让他看”继续使用 `CharacterSocialProfile.canViewMoments`。

整体可见范围与黑名单使用已有 `appCustomizations` 非索引字段保存，所以 IndexedDB 仍是 V18；Backup V12 会自然包含这些记录。
