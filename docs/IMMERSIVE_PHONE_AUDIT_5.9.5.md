# 沉浸式手机审查：5.9.5

本次以用户提供的 `5.9.4-windows-safe-improved.zip` 为审查对象，并以已通过 5.9.4 门禁的正式源码为基线，逐项判断哪些改进适合长期保留、哪些会破坏“真实手机 / 长期陪伴”的体验。

## 保留并整合

### 向量语义记忆

保留 `embeddingService`、历史 Memory 向量回填，以及混合召回逻辑。启用后，记忆检索可同时使用语义相似度、关键词、重要度和时间；不配置 embedding 时继续使用原方案。该能力属于后台基础设施，不在普通聊天里展示技术细节。

### 记忆巩固与衰减

保留长期 Memory 的后台巩固能力，但改为静默运行。巩固只新增摘要型长期记忆和调整低价值记忆权重，不删除原始聊天，也不在对话中插入系统式“记忆巩固完成”消息。

### SafeRichHtml 手机适配

保留窄屏宽度归一、媒体自适应和表格固定布局，降低角色卡 / 社区 HTML 在手机屏幕横向溢出的风险。

### 模型设置、Persona 与导入工具改进

保留 embedding 配置 / 测试 / 回填入口、Persona 关系模板与试聊工具、角色卡导入报告等偏设置和管理场景的增强。这些功能适合出现在设置或编辑页面，不挤进普通聊天界面。

### 设计 Token 基础

保留设计 token 与旧变量兼容映射，作为后续统一视觉的基础。

## 移除或不合并

### 普通聊天 👍 / 👎

移除。它更像模型评测界面，而不是两个人在手机上聊天。普通对话只保留真实聊天需要的消息、回复、语音、图片、撤回等行为。

### “参考了 X 条记忆”折叠面板

不在普通聊天渲染。记忆召回信息仍可作为内部生成元数据保存，但不让角色在每句话后暴露模型工作过程。

### 实验性动态高度虚拟列表

本版不合并。审查发现该实现依赖给 `ChatMessageItem` 组件 ref 直接做 HTMLElement 测量，而 Vue 组件 ref 并不等同于 DOM HTMLElement，存在高度测量失效、空白和滚动跳动风险。当前保留已验证稳定的消息列表；之后如需要千条消息优化，应以真实元素测量和自动化滚动回归测试为前提单独推进。

## 用户截图问题

### 穿搭“换衣服没动”

原因是 V1.4 的大区域使用静态插画，而真正游戏 sprite 只显示在小角落，所以视觉上并非同一个角色系统。V1.5 删除静态大插画路径，穿搭主预览与套装卡片直接使用游戏共享的 `CompanionPixelAvatar`。因此换衣、换色、配饰会马上反映在大预览，游戏也读同一份 Appearance Profile。

### 会话列表红线

滑动删除容器此前整体使用红色背景，而白色会话行使用 GPU `translate3d` 位移。浏览器在某些缩放 / DPR 下会露出约 1px 的父层红色底，形成横贯列表的细线。修复后 swipe row 本身为白色并建立独立层叠上下文，红色仅属于右侧隐藏的删除按钮。

## 沉浸原则

普通聊天优先模拟真实通讯工具；AI 调试、评分、检索解释、模型测试属于设置 / 管理 / 调试空间。Memory 可以很强，但不应每句话都向用户展示“我是如何检索 Memory 的”。Avatar 可以风格化，但同一角色在穿搭与游戏中的实时外观必须来自同一个 runtime 和同一份数据。
