# V0.5.0-alpha.5.2.2 Release Manifest

## Scope

Generation Runtime phase 3. This release moves Community UI repair orchestration and post-generation state/memory/character side effects out of `ChatRoom.vue`, while preserving real-provider-only semantics and all existing data schemas.

## Runtime changes

- Added `src/runtime/generation/communityUiRepairRuntime.ts`.
  - Owns Community UI contract validation, historical state carry-forward, local repair, compact regex/XML state-completion requests, one-shot non-regex AI correction, token-limit degradation, first-response fallback and final rich-HTML user-message ownership filtering.
  - The Runtime never invents local character prose. Failed repair always falls back to the first real Provider response.
- Added `src/runtime/generation/assistantStateEffectsRuntime.ts`.
  - Owns conversation-state patch planning, active resource session state, Lorebook timed-runtime persistence, state-history recording, subjective observation memory writes and Character mood/activity synchronization.
  - Alternative replies are explicitly side-effect free.
- `ChatRoom.vue` now delegates both concerns and drops from about 4128 lines to about 3930 lines.
- Community UI repair now reparses the final canonical assistant text before finalization, preventing repaired `rawContent` from diverging from parsed status/actions.

## Regression coverage

Added 18 direct Runtime tests across two new test files, plus 4 View/Runtime boundary regression tests:

- `communityUiRepairRuntime.test.ts` — 9 cases covering inactive/already-valid contracts, carry-forward, local compiler repair, compact regex/XML state completion, token-limit fallback, general AI correction, total-failure fallback and ownership filtering.
- `assistantStateEffectsRuntime.test.ts` — 9 cases covering resource enter/exit, no-op state plans, Lorebook timed state, observation importance, memory-disabled behavior, alternative-reply isolation, and coordinated state/history/memory/Character side effects.
- `generationRuntimeBoundary.test.ts` — 4 source-boundary cases preventing Community UI/state side-effect logic from drifting back into `ChatRoom.vue`, asserting repair→parse→finalize ordering and keeping the View below 4000 lines.
