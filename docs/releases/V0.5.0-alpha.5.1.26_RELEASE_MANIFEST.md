# V0.5.0-alpha.5.1.26 Release Manifest

## Scope

Release-safety hardening only. No IndexedDB schema, backup schema, chat runtime, character runtime, memory semantics, or Launcher layout schema changes.

## Added

- `scripts/release-safety.mjs`
  - validates `package.json` / `package-lock.json` version identity;
  - validates `.gitignore` protection for `node_modules/`, `dist/`, `*.tsbuildinfo` and `.env*`;
  - validates deterministic `.gitattributes` policy;
  - validates required UTF-8 Chinese documentation and the current release manifest;
  - provides Git preflight, post-sync and staged-area guards, with an optional target repository path for bootstrap preflight;
  - rejects ignored-but-tracked or forbidden tracked/staged paths.
- npm scripts:
  - `release:source-check`
  - `release:git-preflight`
  - `release:git-working`
  - `release:staged-check`
- `npm run verify` now includes the release source-safety check after tests and production build.

## CI

GitHub Pages Actions now calls the same canonical `npm run verify` quality gate used by local release validation.

## Release contract

Windows deployment must still perform two full `npm ci` + `npm run verify` passes: once in the extracted release tree and once after syncing into the clean Git repository. Git preflight and staged checks run before commit.
