# V0.5.0-alpha.5.3.2 Release Manifest

## Scope

Feature release: **时光 / 共同回忆 V1.2 · Shared Event Runtime**. This release converts the evidence list into an event-aware timeline while preserving provenance for every underlying record.

## Feature surface

- New `sharedTimelineEventService.ts` builds deterministic multi-evidence events.
- Same-source memory/state records can collapse into one event.
- Nearby chat/media/moment evidence can be conservatively grouped by character, conversation, time window and text overlap.
- Different characters are never auto-merged; an auto event cannot span more than 8 hours.
- Default timeline view is now **事件**, with an **证据** view kept for source-level inspection.
- Event detail sheet shows date range, image gallery, evidence chain and a direct jump to every original source.
- Users can select multiple evidence rows and manually merge them into a named event.
- Manual events can be renamed, starred, hidden or split without deleting any source evidence.
- Deep-linkable event detail uses `/app/时光?event=<eventId>`.
- Proactive old-memory bridge now selects a verified event and supplies both event id and evidence ids to the prompt guard.

## Truth / persistence boundary

- Shared Events never create new facts and never copy evidence text into a new IndexedDB store.
- Manual groups persist only event metadata + evidence ids in `appCustomizations.sharedTimelineState.eventGroups`.
- Unknown, missing or overlapping manual group members are normalized conservatively.
- Provider failure policy is unchanged: no local role-reply fabrication.

## Persistence

- IndexedDB V18 unchanged.
- Backup V12 unchanged.
- Launcher Grid V13 / HomeLayout revision 12 unchanged.
- No migration or site-data reset required.

## Test matrix
