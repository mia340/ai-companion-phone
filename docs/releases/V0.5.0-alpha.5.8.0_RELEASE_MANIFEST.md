## Main changes

- `coupleBoardInteractionService.ts`: persistent per-game interaction ledger; builds character context from role card, Conversation State, relevant long-term Memory and Shared Timeline; AI reply evidence validation; no fixed romance reaction categories; second-pass Role Continuity Audit with one repair attempt.
- `coupleBoardMemoryBridge.ts`: completed interaction writes an evidence-safe shared event to character-scope Memory, then optionally extracts stable semantic memories. Hypothetical/transient candidates are not persisted as facts.
- `coupleBoardMapService.ts`: preserves the legacy 0..29 rules index while mapping it to a 30-stop themed date route.
- `CoupleBoardPixelSprite.vue`: full-body CSS pixel people with idle/walk presentation and reduced-motion support.
- `CoupleBoardView.vue`: role auto-roll, step-by-step map movement, pixel/romantic presentation modes, resumable live interaction, multi-turn conversation, role natural-close signal, Memory Bridge integration.
- `CoupleBoardLibraryView.vue`: V2 labeling and archive/Memory responsibility wording.
- `COUPLE_BOARD_V2.md`: architecture, memory semantics, OOC/evidence rules, lifecycle, current Alpha boundaries and acceptance checklist.

## Role continuity / Memory rules

1. Role card and existing relationship context have priority over game atmosphere.
2. No fixed “shy / jealous / flirt back” reaction table controls role behavior.
3. If a role claims a concrete shared past, returned evidence ids must belong to the allowed Memory / Timeline set.
4. Single-person questions only decide who starts. Both sides must actually respond before the interaction can be completed.
5. Completed interaction stores what was actually said as a shared event. It does not turn the question's premise into a fact.
6. Stable semantic extraction accepts only `kind=stable`; hypothetical/transient rows are discarded.
7. Game memories use character scope, so later normal chat and other role contexts can retrieve them.

## Compatibility

- Existing V1/V1.4 game saves remain parseable; absent `settings.visualMode` is treated as the romantic presentation when restored.
- No Dexie store or IndexedDB version is added.
- Interaction ledgers are stored in `appCustomizations` and therefore travel through the existing Backup V12 payload.
- Existing 160-question V3 library, L1-L5 18+ boundary, content center, event cards and archive are retained.
