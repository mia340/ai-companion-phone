# AI Companion Phone 开发日志

## 2026-07-23（V0.0.6）

### 今日目标

完成本地角色化回复，使不同角色能够依据人设、说话方式、关系、心情与活动表现出明显差异，同时梳理开发测试环境中的数据隔离问题。

### 今日完成

#### ① 本地角色化回复

升级：

`src/services/ai/provider.ts`

新增角色上下文：

- 角色姓名
- 身份或职业
- 核心人设
- 说话方式
- 背景故事
- 与用户的关系
- 当前心情
- 当前活动
- 喜欢与不喜欢
- 用户昵称与个人简介
- 最近对话记录

当前仍为本地规则模拟，但已经验证了统一 Provider 接口和角色上下文组织方式。

#### ② 角色语气差异

已验证：

- 林夏：温柔、细腻、主动关心
- 顾言：安静、克制、偶尔毒舌
- 自建角色：根据导入的人设和说话方式生成不同风格回复

#### ③ AI 提示词基础结构

聊天页开始组装系统提示信息，并明确要求：

- 始终以当前角色身份回答
- 不提及模型、API、Mock 或系统提示
- 避免机械复述用户原话
- 回复符合当前角色设定

#### ④ 确认浏览器数据隔离问题

发现：

- 外部 Edge 浏览器中存在苏晚及完整聊天记录
- VS Code 内置浏览器只存在初始化角色
- 两个环境虽然访问同一地址，但使用独立 IndexedDB 与 localStorage

结论：

苏晚并未丢失，而是不同浏览器环境的数据互不共享。

处理：

- 固定使用外部 Edge 作为主要测试环境
- 删除临时的苏晚自动恢复逻辑
- 后续增加数据导出、导入与备份功能

### 今日踩坑

#### 问题一：误以为角色数据丢失

现象：

VS Code 内置浏览器中没有苏晚。

真实原因：

外部 Edge 和 VS Code 内置浏览器拥有各自独立的浏览器数据库。

解决：

统一测试环境，并将“数据导出与备份”列为下一阶段重要任务。

#### 问题二：临时恢复模块造成额外复杂度

曾创建：

`src/db/integrity.ts`

用于根据会话恢复角色。

进一步确认数据未丢失后，该模块不再必要，应删除，避免未来用户主动删除角色后又被自动恢复。

### 当前结果

项目已经具备：

- 多角色独立聊天
- 用户与角色头像
- 本地消息持久化
- 基础角色化回复
- 可替换 AI Provider 接口

### 当前版本

V0.0.6

### 下一步计划

- 角色详情与编辑
- 角色删除与关联数据清理
- 数据导出、导入与备份
- 接入真实 AI 模型
- 基础短期记忆

### 今日踩坑

#### 问题一：文件名大小写不一致

实际文件名与导入路径出现：

`userprofile.ts`

和：

`userProfile.ts`

不一致。

解决：

统一文件名为：

`userProfile.ts`

并同步更新所有导入。

#### 问题二：tsconfig.node.json 构建失败

报错：

`TS5096: allowImportingTsExtensions can only be used when noEmit or emitDeclarationOnly is set`

解决：

在：

- `tsconfig.app.json`
- `tsconfig.node.json`

中加入：

`"noEmit": true`

### 当前结果

用户资料保存后，聊天中的用户头像会同步更新，刷新浏览器后仍然保留。

### 今日踩坑

#### 问题一：照片头像显示为长字符串

原因：

照片以 Base64 保存，但页面使用文本插值直接渲染。

解决：

使用 `CharacterAvatar.vue` 判断图片类型并以 `<img>` 显示。

#### 问题二：点击苏晚进入顾言

原因：

通讯录路由逻辑写死。

解决：

使用角色 ID 与 Conversation.memberIds 建立关联。

#### 问题三：林夏重复显示

原因：

林夏同时属于“特别关心”和“朋友”。

解决：

分组展示时使用角色 ID 集合去重。

#### 问题四：聊天头像横向拉伸

原因：

CSS 选择器影响了头像组件。

解决：

只让状态文字占据剩余空间，不再对所有直接子 `span` 应用 `flex: 1`。
